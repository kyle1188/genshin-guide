从零搭建《原神》攻略互动站 · 实战教程

本文整理自一个真实项目：从「查攻略」到「网站上线 + Google 收录」的完整过程。
目标不是做一个普通攻略站，而是做出比头部攻略站更好用的站——靠「互动工具 + 双语 + 免费部署」三件事拉开差距。
部署与 Google 收录的单独教程见《部署教程-Git到GitHub到Vercel》《教程-Google收录与GSC》，本文聚焦「建站本身」。

0. 项目目标与打法

我们定的胜负手：

维度 头部攻略站 我们的做法
内容 图文攻略，千篇一律 攻略 + 5 个可交互工具（独家）
语言 基本只有中文 国内中文 / 海外英文自动切换
部署 各自为政 Git 自动部署，地址永不变
收录 靠权重 长尾词 + 外链 + hreflang 多语

核心思路：大站做不好的「交互」和「多语长尾」，正好是我们能吃下的流量。

1. 内容研究：先写出有竞争力的攻略文档

不要上来就写代码。先有高质量内容，站才有价值。

1.1 调研来源

  • 官方 wiki、社区攻略、玩家实测数据
  • 不照搬，做「整合 + 结构化」：把零散信息整理成可执行的新手路径

1.2 产出三份文档

  1. 《原神攻略总览》：世界观、系统、资源体系一图流
  2. 《新手开荒 30 天日程》：每天做什么，零基础跟练
  3. 《零氪专属开荒顺序》：不花钱也能变强的最优路线

1.3 定位要点

  • 面向新手，不是给老玩家看的数据报告
  • 非官方但严谨：标注「个人整理，非官方」，避免误导
  • 每篇都要有「别的站没说清」的增量信息

文档是网站的原材料。文档质量 = 网站底座质量。这一步偷懒，后面再好看也留不住人。

2. 网站搭建：单页静态站

技术选型原则：简单、能跑、好维护、免费部署。

2.1 选型

  • 纯静态：HTML + 内联 CSS + 内联 JS，单文件 index.html
  • 不引入框架/构建工具：免依赖、免打包、Vercel 直接认
  • 深色原神风：金 + 蓝配色，圆角卡片，悬浮微动效

2.2 文件结构

genshin-guide/
├── index.html        # 主站（含双语 371 对 .zh/.en、5 个工具、i18n、SEO）
├── assets/           # 4 张 AI 生成的图（Hero/元素光效/冒险者/星图）
├── vercel.json       # {"version":2,"outputDirectory":"."}
├── sitemap.xml       # 含 hreflang
├── robots.txt        # 指向 sitemap
└── 各教程.md / .docx

2.3 为什么单文件

  • 部署零配置：Vercel 直接托管单个 HTML
  • 改内容 = 改一个文件，维护心智成本低
  • 双语靠 data-lang 切换，无需多套页面

3. 补齐头部攻略站的弱点：加互动工具

这一步是拉开差距的关键。头部站几乎都是「图文 + 视频」，没人做交互。我们做 5 个工具，用户一来就「玩」住。

3.1 弱点对照（我们补的）

头部站弱点 我们的工具
无实时数据 抽卡模拟器、原石规划器
元素反应讲不清 元素反应演示（SVG/CSS 动画）
配队凭感觉 配队共鸣计算器
开荒无反馈 开荒进度打卡（localStorage）

3.2 五个工具清单

  1. 抽卡模拟器：90 抽 5★保底、10 抽 4★保底
  2. 元素反应演示：点击元素看反应动画
  3. 原石规划器：输入每日/活动原石，估算出金周期
  4. 配队共鸣：选角色自动算元素共鸣加成
  5. 开荒进度打卡：勾选任务存 localStorage，刷新不丢

3.3 关键代码模式（抽卡保底修复）

坑：出 5★ 时若没同时重置 4★ 计数器，会导致 4★ 保底延迟到 11 抽才触发。

修复后（正确）逻辑：

if (rarity === 5) {
  GS.p5 = 0;   // 5★ 计数清零
  GS.p4 = 0;   // 4★ 计数也清零（关键！）
  GS.c5++;     // 5★ 数量 +1
  // ... 发奖逻辑
}

测试验证：连续抽 1000 次，4★/5★ 保底触发误差为 0。

3.4 工具重渲染与 i18n 协同

每个工具渲染函数要接受当前语言参数，切语言时整体重渲，避免中英混排。

4. 国际化 i18n：国内中文 / 海外英文

这是吃海外 Google 流量的关键（搜 Genshin starter guide 等）。

4.1 方案

  • <html data-lang="zh|en"> + CSS 用 [data-lang="zh"] .en { display:none } 之类切换显隐
  • 全站文案用 .zh / .en 双份标记

4.2 IP 检测三级回退

// 1) 优先：ipapi.co（国内/海外 IP 库）
// 2) 备胎：ip-api.com
// 3) 兜底：navigator.language（浏览器语言）

谁先返回用谁，避免单点失败整站卡英文。

4.3 防闪烁

在 <head> 里同步执行一段内联脚本，HTML 还没渲染就定好语言，避免「先英后中」闪一下。

4.4 手动切换 + 记忆

  • 页面右上角放「中 / EN」按钮
  • 选择写入 localStorage，下次直接读，不再走 IP 检测

4.5 hreflang（SEO 必需）

sitemap.xml 里给同一页配三行：

<xhtml:link rel="alternate" hreflang="zh-CN" href="https://你的域名/" />
<xhtml:link rel="alternate" hreflang="en"     href="https://你的域名/" />
<xhtml:link rel="alternate" hreflang="x-default" href="https://你的域名/" />

告诉 Google：中英文是同一页的不同语言版本，别当重复内容惩罚。

5. SEO 地基（上线前必做）

项 做法
title / OG 按语言 中文版、英文版分别设 <title> 和 OG 描述，提升对应语言搜索命中
JSON-LD 结构化数据，帮助 Google 理解站点类型
sitemap.xml 列出所有语言链接（见 4.5）
robots.txt 放行爬虫 + 指向 sitemap
验证码 meta GSC 验证用（见收录教程）

换域名时全局搜索所有旧域名（不只 vercel.app 模式）——我们曾漏掉一个 hreflang 里的 CloudStudio 旧地址，导致英文链接指向死站。

6. 部署与收录（交钥匙给另两篇）

  • 部署：Git → GitHub → Vercel 自动部署，详见《部署教程-Git到GitHub到Vercel》
  • 收录：GSC 验证 + sitemap 提交 + 请求索引，详见《教程-Google收录与GSC》

本文解决「站怎么做出来」，那两篇解决「站怎么上线被搜到」。三篇合起来 = 一个站从 0 到被 Google 收录的完整链路。

7. 踩坑复盘（省你三小时）

坑 现象 解法
分支错配 Vercel 部署出旧项目（默认拉 main，代码在 master） 把代码强推到 main，旧项目备份到 backup-old-main
地址每次变 每次拖文件夹上传生成新 vercel.app 地址 用 Git 关联，地址固定
GSC 验证失败 选了「HTML 文件」法却没放文件 改选「HTML 标记」法，加一行 <meta>
请求索引超限 当天点太多次被限流 等明天，配额自动重置，不影响收录
域名替换遗漏 只替换主模式，漏掉 hreflang 旧地址 换域名时全局搜所有旧域名

8. 可复用的命令速查

# 新项目初始化 + 建 GitHub 仓库 + 推送（一条龙）
git init
git add -A
git commit -m "initial"
gh repo create 项目名 --public --source=. --push

# 日常更新
git add -A && git commit -m "改XX" && git push

# 同步到 Vercel 默认分支（若代码在 master、仓库默认 main）
git push origin master:main
